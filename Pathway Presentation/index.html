Pathway.
The platform layer that makes the February rebrand possible, and compounds beyond it.
The problem
Every module built separately.
Every team solving the same
problems differently.
Every new feature makes it worse. This is what generates engineering rework, support tickets, and an inconsistent product experience across every module. Every sprint, teams reimpliment things that already exist elsewhere. Every release adds new inconsistency.
What Pathway is
Platform infrastructure.
Not a design project.
The same way a shared API or database architecture enables every team to build on a common foundation, Pathway enables every front-end team to build from a shared, governed component library.

One source of truth. One token architecture. One component library. Every team builds from it.
Tokens
Design tokens as CSS custom properties and JSON. One change here propagates to every component across every module.
Components
React component library built on token foundations. Versioned, documented, and testable.
Storybook
Living component documentation. Engineers reference this, not Figma annotations or PDFs.
Governance
Contribution model, review gates, and versioning. The system stays coherent as it grows.

What is missing
The system exists.
What it needs is proper ownership.
Pathway is a platform layer. It requires a dedicated team assigned to it permanently, the same way any critical platform infrastructure has dedicated ownership. Not two people running it as a side initiative. A properly resourced team with allocated time, clear mandate, and the engineering and design capacity to build, govern, and evolve the system continuously.
Principal Experience Designer
Owns the system vision, direction, and quality bar. Permanent. Platform infrastructure ownership, not a project role that hands off at launch.
Dedicated Design System Engineer
Owns the pipeline, governance, token architecture, Storybook, and code connect. Also permanent. The system drifts immediately without continuous engineering ownership.
Two additional asks
Tooling and alignment.
Figma Organisation plan upgrade
Branching, versioning, design system analytics, and full code connect are unavailable on the current plan. These are not optional features. They are the technical mechanisms that make the pipeline work and connect Figma to the production codebase. The upgrade cost is negligible relative to the engineering hours currently lost working around its absence.
Engineering mandate across all tribes
Front-end engineers across all modules need to build from the Pathway repo and use Figma dev mode as the implementation reference. A clear expectation from engineering leadership, a one-time alignment session, and accountability for implementation accuracy. This is what turns the infrastructure investment into product reality.
The ask
Three things.
1
A dedicated team assigned permanently to Pathway as a platform layer.
A principal experience designer and a dedicated design system engineer. Both permanent. Both full time. Not borrowed. Not contracted to February.
2
A Figma Organisation plan upgrade.
The non-negotiable tooling dependency that enables code connect, branching, and versioning. Without it the pipeline cannot reach stage two.
3
Engineering leadership mandating all front-end teams build from Pathway.
The system is built. The workflow is working. This is what turns it from a parallel environment into the production standard.
